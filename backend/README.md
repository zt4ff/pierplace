# PierPlace Backend (FastAPI + Postgres)

Implements `docs/piscine-backend-contract.md`. The REST API and the presence
WebSocket are served from the same ASGI app.

## Run locally (bare metal, no Docker)

Start a local PostgreSQL and create an owned database, then:

```sh
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # set PIERPLACE_DATABASE_URL for your Postgres
python -m app.seed        # idempotent: floors, tables, seats, levels, templates
python -m app             # ONE command: REST API + WebSocket
```

`python -m app` serves `http://localhost:8000` and `ws://localhost:8000/ws`.
Override with `PIERPLACE_HOST`, `PIERPLACE_PORT`, `PIERPLACE_RELOAD`.

The `.env` file is loaded automatically. On Debian/Ubuntu the local Postgres can
be reached over the unix socket without a password, e.g.
`postgresql+asyncpg://<os-user>@/pierplace?host=/var/run/postgresql`.
Otherwise use a TCP URL like
`postgresql+asyncpg://pierplace:pierplace@localhost:5432/pierplace`.

### Live lobby (presence)

- `GET /health` — liveness.
- `WS /ws` — players send `{type:"join", profile, floor}` then
  `{type:"move", x, y, seated, tableId, floor}`. The server persists the
  character to `users` and fans out `welcome` / `joined` / `moved` / `left`.
- `GET/POST /tables/{table_id}/messages` — table chat persisted in
  `chats`/`messages`, isolated per table.

## Deploy to Render (issue #1)

`render.yaml` is the blueprint: managed Postgres 16 + FastAPI web service
with `/health` checks. Apply via Dashboard → New → Blueprint on this repo.

- The app reads `DATABASE_URL` (Render's `postgres://` string) automatically
  and upgrades it to asyncpg; local `PIERPLACE_DATABASE_URL` still wins when
  set. `PIERPLACE_JWT_SECRET` is generated by Render.
- Seeding is automatic: `preDeployCommand` runs the idempotent
  `python -m app.seed` on every deploy (creates `citext` extension + all
  tables + content; safe to re-run). Use the service Shell tab only to
  verify or to reseed manually.
- Free-plan Postgres sleeps when idle; first request after sleep is slow.

## Team notes
- Auth: `POST /auth/register|login` (username+password, additive to game-pass).
  JWT bearer reused for HTTP + WS.
- Rejoin: `GET /me/state?run_id=` + replay undelivered/unread `/notify/inbox`.
- Locks: illegal moves 403 `locked`; dead laptop 409 `battery_dead` on submit/open.
- Defense: 30s total, timeout=fail, one shared answer box, pass shares 50 each.
- Board: `GET /xp/board?level=` (25 fixed bands, top 1190). `GET /xp/me` for self.
- Location: `POST /location/move` (403 when locked), `GET /location/me|roster`.
- Piscine: `PATCH /piscine/runs/{id}/threshold` (mentor), briefing-floor, food-floor-status.
- Work: `GET /quests/tasks`, raid groups + `POST /raids/defenses/open` (+30s),
  `GET /checkpoints/unlocked` (100% bar gates next), quest best-kept.
- Social: `GET /notify/inbox` (unread-first replay), `GET /laptops/me` HUD.
- Mentors: `GET /mentors/activity|id-card`, `POST /mentors/triggers/handle`;
  behavior attend (briefing 20/assembly 10) + chat-participation (5).
- WS events (relay only, no writes): piscine.started, event.warned/started/closed,
  lock.applied, seat.ejected, chat.message, xp.awarded, level.up, battery.low,
  trigger.created, meeting.called, memo.sent, food.on_floor, defense.opened/decided.
